## S00-001：日志 crate 可编译

### 1. 功能目标
本功能属于 S00。建立所有组件共享的单行文件日志、运行链 UUID、线程协程身份、真实调用点和安全脱敏能力。 本项聚焦于日志上下文和文件写入，必须形成可以独立启动、测试或演示的最小闭环。

### 2. 范围与边界
- 包含：日志 crate 可编译所需契约、状态转换、错误返回、日志事件和自动化验收。
- 不包含：未列入本阶段的真实 Provider、跨阶段优化或视觉润色；依赖能力只能通过 Port、Fake 或 fixture 接入。
- 上游依赖：无。依赖未 verified 时，本功能只能处于 blocked。
- 主要产物：日志文件、运行链 UUID、序号和关闭结果。

### 3. 输入、输出与处理流程
输入来自上游命令、查询、事件、配置、用户动作或 fixture，必须具备稳定标识、版本和必要授权上下文。

处理顺序：首先校验格式、当前状态、权限和依赖版本；其次，围绕功能 [日志 crate 可编译] 完成输入校验、领域处理、持久化或投影、用户反馈和可重复验收。；然后产生领域事件或标准结果并更新必要投影；最后返回成功、等待、失败或取消结果，并记录阶段进度。

输出为日志文件、运行链 UUID、序号和关闭结果。计划中的最小验收为：cargo check -p apex-observability。

### 4. 状态、数据与一致性
- 状态变化必须遵守领域模型与事件规范，禁止直接修改 projection 绕过 domain command。
- SQLite Event Store，或本阶段明确声明的 Fake Store，是业务事实来源；日志只用于诊断。
- 外部副作用必须具有 operation_id、幂等策略、取消边界和恢复结论。
- 并发写入遵循单写者或 Write Claim；查询需要说明一致性级别和 cursor。

### 5. 异常、取消与恢复
必须设计输入无效、依赖不可用、权限拒绝、超时、用户取消、进程重启和重复提交路径。每类路径都要定义稳定 error_code、用户提示、是否可重试、是否产生事件和重启动作。不安全时进入明确的 blocked、failed 或 interrupted，不能静默成功。

### 6. 日志与安全要求
入口初始化日志，记录 stage.started、关键进度、stage.completed 或 stage.failed。日志采用非 JSON、非 key=value 的单行位置式格式：时间、级别、PID、任务链 UUID、线程或协程、logger、最后一级文件名和行号、主消息。不记录客户端地址；诊断上下文仅在 DEBUG 级别展示并置于主消息前，INFO 及以上隐藏。不得使用 JSON 或 key=value，不得记录客户端地址、绝对路径和敏感正文。

### 7. 测试与可运行验收
- 必须提供 cargo 命令、CLI 子命令、集成测试或可重复 demo。
- 至少覆盖成功、失败、取消、重复调用以及适用的恢复或回滚路径。
- 日志断言任务链 UUID、稳定 message code、进度闭环、真实文件名和行号、无敏感信息泄漏。
- 回滚只能删除本阶段临时产物或恢复快照，不得删除用户数据或覆盖外部修改。

### 8. 后续代码注释要求

输入来自上游命令、查询、事件、配置、用户动作或 fixture，必须具备稳定标识、版本和必要授权上下文。

处理顺序：首先校验格式、当前状态、权限和依赖版本；其次，围绕功能 [`v0.0.5` demo] 完成输入校验、领域处理、持久化或投影、用户反馈和可重复验收。；然后产生领域事件或标准结果并更新必要投影；最后返回成功、等待、失败或取消结果，并记录阶段进度。

输出为领域事件、查询投影、日志和验收结果。计划中的最小验收为：重启后会话和消息恢复。

### 4. 状态、数据与一致性
- 状态变化必须遵守领域模型与事件规范，禁止直接修改 projection 绕过 domain command。
- SQLite Event Store，或本阶段明确声明的 Fake Store，是业务事实来源；日志只用于诊断。
- 外部副作用必须具有 operation_id、幂等策略、取消边界和恢复结论。
- 并发写入遵循单写者或 Write Claim；查询需要说明一致性级别和 cursor。

### 5. 异常、取消与恢复
必须设计输入无效、依赖不可用、权限拒绝、超时、用户取消、进程重启和重复提交路径。每类路径都要定义稳定 error_code、用户提示、是否可重试、是否产生事件和重启动作。不安全时进入明确的 blocked、failed 或 interrupted，不能静默成功。

### 6. 日志与安全要求
入口初始化日志，记录 stage.started、关键进度、stage.completed 或 stage.failed。日志采用非 JSON、非 key=value 的单行位置式格式：时间、级别、PID、任务链 UUID、线程或协程、logger、最后一级文件名和行号、主消息。不记录客户端地址；诊断上下文仅在 DEBUG 级别展示并置于主消息前，INFO 及以上隐藏。必须保持 Port、幂等、取消、恢复和审计边界。

### 7. 测试与可运行验收
- 必须提供 cargo 命令、CLI 子命令、集成测试或可重复 demo。
- 至少覆盖成功、失败、取消、重复调用以及适用的恢复或回滚路径。
- 日志断言任务链 UUID、稳定 message code、进度闭环、真实文件名和行号、无敏感信息泄漏。
- 回滚只能删除本阶段临时产物或恢复快照，不得删除用户数据或覆盖外部修改。

### 8. 后续代码注释要求
编码前必须通过本条目审核。实现代码需要为公共类型和函数、状态转换、协议字段、数据库迁移、异步任务边界、错误分支和安全判定添加中文详细注释。注释应解释设计原因、约束和失败恢复；复杂算法、并发或锁、取消传播、幂等键和安全边界还要写明前置条件、后置条件及不变量。测试代码需要说明 fixture 意图和验收理由。
